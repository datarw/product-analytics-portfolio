## Решение по выбору

Основной датасет проекта: **Online Retail II (UCI)**, выбран 2026-10-25. Удовлетворяет
критериям 1–4; критерий 5 (канал, гео) не выполнен — канал синтезируется для дашборда.
Olist, Instacart, KKBox — не основа (см. карточки).
Критерии выбора, в порядке важности:

1. Есть `customer_id` и повторные покупки → иначе LTV-модель не строится.
2. Есть временная метка транзакции с точностью до дня → нужны когорты и holdout.
3. Есть сумма транзакции → нужна денежная часть LTV.
4. Период ≥ 12 месяцев → нужен запас на calibration/holdout split.
5. Желательно: канал привлечения или гео → для юнит-экономики по каналам.

## Кандидаты для LTV и юнит-экономики

### Online Retail II (UCI)
| | |
|---|---|
| Что внутри | Транзакции британского онлайн-ритейлера подарков, ~2009–2011 |
| Объём | ~1 млн строк (две склейки по годам) |
| Ключевые поля | `Invoice`, `StockCode`, `Quantity`, `InvoiceDate`, `Price`, `Customer ID`, `Country` |
| Годится для | LTV (BG/NBD + Gamma-Gamma), RFM, когорты, market basket |
| Известные проблемы | Пропуски в `Customer ID` (22,8% сырых строк); возвраты как отрицательный `Quantity`; тестовые и служебные `StockCode`; выбросы по цене |
| Канал привлечения | Нет → юнит-экономика по каналам не строится напрямую |
| Лицензия | CC BY 4.0 (требуется атрибуция). Chen, D. (2012). Online Retail II. UCI ML Repository, DOI 10.24432/C5CG6D |
| Ссылка | https://archive.ics.uci.edu/dataset/502/online+retail+ii · файл `online_retail_II.xlsx` (43,5 МБ) → `data/raw/online-retail-ii/` |
| Статус | ✅ проверено 2026-10-25 (страница UCI, лицензия, фактические объёмы и период) |

**Факты по загруженному файлу** (сверено 2026-10-25, `case_ltv/notebooks/01-load-and-profile.ipynb`):
1 067 371 строк, 5 942 клиента в сырых данных, 2009-12-01 → 2011-12-09 (24,2 мес;
декабрь 2011 неполный). Описание автора: оптовики составляют заметную долю клиентов.

**Чек-лист чистки** (порядок важен; `case_ltv/src/data.py`):

| Шаг | Удалено строк | Осталось строк | Клиентов |
|---|---|---|---|
| сырые данные | — | 1 067 371 | 5 942 |
| точные дубликаты | 34 335 | 1 033 036 | 5 942 |
| пустой `Customer ID` | 235 151 | 797 885 | 5 942 |
| служебные коды (`POST`, `DOT`, `M`, `D`, `C2`, `S`, `B`, банк, ваучеры `gift_*` и др.) | 3 660 | 794 225 | 5 876 |
| `Price` ≤ 0 | 60 | 794 165 | 5 875 |
| клиенты только с отменами (нет первой покупки) | 87 | 794 078 | 5 852 |

Отмены (счёт с префиксом `C`) не удаляются, а остаются отрицательными строками:
доля отмен 4,2% выручки продаж. Две пары «заказ — полная отмена» (клиенты 16446 и 12346,
±168 469,6 £ и ±77 183,6 £) — при фильтре «убрать отрицательные» дали бы выбросы.
27,6% клиентов имеют ровно одну покупку (сегмент B).

**Комментарий.** Канонический датасет для вероятностных LTV-моделей — плюс в том,
что есть с чем сверить результат; минус в том, что он разобран в сотне туториалов.
Дифференцироваться придётся не датасетом, а глубиной валидации.

### Olist Brazilian E-Commerce (Kaggle)
| | |
|---|---|
| Что внутри | Заказы бразильского маркетплейса 2016–2018, 9 связанных таблиц |
| Объём | ~100 тыс. заказов |
| Ключевые поля | заказы, позиции, платежи, отзывы, продавцы, клиенты, гео |
| Годится для | Юнит-экономика, воронка, гео-сегментация, NPS/отзывы |
| Известные проблемы | **Очень низкая доля повторных покупок** → вероятностные LTV-модели недоопределены; `customer_id` меняется между заказами, склейка через `customer_unique_id` |
| Лицензия | Проверить (CC BY-NC-SA, уточнить) |
| Статус | ⬜ не проверено |

**Комментарий.** Разреженность повторных покупок — не дефект, а содержательный
поворот: кейс может показать, *почему* BG/NBD здесь не применяется и что делать вместо.

### Синтетика для блока «дизайн эксперимента»
Часть A/B-кейса — не анализ готового теста, а **проектирование**: расчёт MDE,
мощности, длительности, симуляция подглядывания, проверка CUPED, сравнение
коррекций на множественные сравнения. Здесь генерация данных уместна и честна,
потому что предмет демонстрации — поведение процедуры, а не вывод о бизнесе.
Симуляции помечать явно, в отдельном ноутбуке, с указанием параметров генератора.
