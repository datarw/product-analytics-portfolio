# AGENT.md — правила работы в репозитории

Публичная версия рабочих правил. Мастер-копия и рабочие журналы лежат вне репозитория. При конфликте приоритет у `docs/conventions.md`.

## Что это за репозиторий

Портфолио продуктового аналитика: три кейса — LTV, A/B, дашборд. Публикуются код, ноутбуки с выводом, графики, README и тесты. Данные, библиотека источников и журналы решений в git не входят.

## Перед первой правкой

1. `docs/conventions.md` — стандарт кейса: порядок секций README, именование, технические правила, шесть проверок §5а, тон текста.
2. `docs/datasets.md` — датасет, чек-лист чистки, известные проблемы.
3. `paths.py` — единственный способ строить пути.
4. `case_ltv/case_ltv.md` (вне git) — журнал решений: что решено и почему, что отвергнуто, что открыто.

## Структура

```
case_ltv/            готовый кейс: src, notebooks 01–10, figures, README
case_ab/             скелет A/B-кейса (в работе)
case_dashboard/      скелет дашборда (в работе)
docs/                снапшоты conventions.md и datasets.md
tests/               unit-тесты без данных
paths.py             пути к data/ и library/ вне репозитория
sync_check.py        аудит синхронизации и гигиены
```

## Данные

- Сырой файл: `<контейнер>/data/raw/online-retail-ii/online_retail_II.xlsx`.
- Очищенная таблица: `<контейнер>/data/processed/transactions.parquet`.
- `raw/` не редактируется; отмены остаются отрицательными строками; пропущенные даты не достраиваются.
- В git не едут `data/`, `ltv-clv-library/`, `analytics-library/`, `journals/` и `case_*.md`.

## Технические правила

- Python 3.12; версии в `requirements.txt` прибиты.
- Один `numpy.random.Generator` из `RANDOM_SEED = 42`, передаётся явно. `np.random.seed`/`np.random.rand` запрещены.
- Пути только через `paths.py`; литеральных `../../data/` в коде нет.
- Ноутбук — один логический шаг. Перед коммитом прогоняется с нуля, вывод сохраняется.
- Чистые функции — в `src/`; графики — в `src/plots.py`, метрики — в `src/metrics.py`, модели — в `src/models.py`.
- Любая цифра README воспроизводится ячейкой ноутбука. Цифр «из головы» нет.
- Все шесть проверок §5а — ассертами в коде, не в тексте.
- Термины английские, проза русская, активный залог, первое лицо.

## Журнал

Новое решение сначала попадает в `case_ltv/case_ltv.md` (дата · решение · основание · отвергнутая альтернатива), потом в код и README. Формат записи:

```
2026-11-16 · <решение> · <почему> · <альтернатива и почему нет>
- следствие: ...
```

## Чего не делать

- Не коммитить данные, библиотеку и журналы.
- Не переписывать `docs/conventions.md` и `docs/datasets.md` без явной просьбы.
- Не добавлять модель без сравнения с бейзлайном B3.
- Не публиковать сравнительное утверждение без метрики, окна, бейзлайна и доверительного интервала.
- Не удалять отмены и не заполнять пропущенные даты.
- Не менять порядок шагов чистки в `case_ltv/src/data.py`: числа в `docs/datasets.md` верны только для него.
